# Pre-registration, v2, addendum 3: E5 (detector 2 dose sweep with the volume-matched statistic) and E6 (mutation test)

Committed before either experiment runs. Same general rules as `PREREG_V2.md`.

## E5. Does the volume-matched statistic repair detector 2, and where does each statistic start to detect?

**Context.** Round 1 showed that detector 2's effect (arm A1 against the no-leak arm A0) is partly corpus size: the corpus-size arm A2 (the same number of extra
SOURCE stays in place of target stays) recovers 0.31 and 0.48 of it at 5% and 20% leakage on the PhysioNet demonstration pair. The shipped detector is not edited.
A volume-matched statistic is a different quantity, computed from the same trained models: the paired relative difference between A1 and A2. We call it the
v2 statistic and the shipped one v1. No threshold changes: both use the one-sided paired t-test over five seeds with critical value 2.132.

**Design.** The round-1 procedure of `task2_values_vs_missingness.py`, unchanged in data, split, model and epochs (900 nominal stays, 3 epochs, seeds 42 to 46), with
new leakage doses 1%, 2% and 10% of the target pool and only arms A1 and A2. Doses 5% and 20% are taken from the round-1 per-seed files (same seeds and
configuration). For each dose: r1 and r2 are the mean relative reductions in probe loss of A1 and A2 against A0; v1 flags if t(r1) is at least 2.132 and v2 flags if
t(r1 - r2) is at least 2.132. The null for both statistics is the round-1 20-replicate comparison of two no-leak arms (1 of 20 flagged, exact 95% interval 0.001 to 0.249);
it is not rerun.

**Reported.** Per dose: r1, r2, r2/r1, t for v1 and v2, and whether each flags; the lowest dose at which each flags. Reading rule fixed now: if v2 flags at a dose where v1
flags and r2/r1 is below 0.5, we say the volume-matched statistic separates target exposure from volume at that dose; if v2 does not flag at a dose where v1 does, we say the
detector's effect at that dose is not distinguishable from volume at five seeds. Neither outcome changes the shipped detector, and the paper keeps v1 as the detector.

**Where.** Local CPU, PhysioNet 2019 only. Script `v2/scripts/e5_detector2_dose_sweep.py`.

## E6. Mutation test of detector 1 and detector 2's decision code

**Question.** If the decision code of a detector is changed in a small, plausible way, does the repository's own test suite (the controls and fixtures) notice?

**Targets.** `detectors/checks/check1_label_shift.py` and `detectors/checks/check2_pretrain_leakage.py`, in a scratch copy of the repository so that no shipped file is edited.

**Mutants, generated by code, fixed now.** Operators applied one at a time to the syntax tree: comparison replaced (< to <=, > to >=, < to >, > to <), boolean operator swapped
(and to or, or to and), `not` removed, arithmetic operator swapped (+ to -, * to /), numeric literal replaced by its value plus one and by zero. Every mutant that still parses is run.

**Run.** The full test suite of `detectors/tests` in the scratch copy with a 180 second timeout and stop at the first failure; PCL_TEST_MODE=1 and the PhysioNet data present. A mutant is
killed if any test fails or the run times out or errors; it survives if all tests pass.

**Reported.** Mutants generated, killed, survived (exact interval on the killed share), and the list of survivors with file and line. Survivors are read by the authors and labelled equivalent
(no behavioural change), dead code, or a gap in the controls; that labelling is reported as our judgement.

**Where.** Local CPU. Script `v2/scripts/e6_mutation_test.py`.
